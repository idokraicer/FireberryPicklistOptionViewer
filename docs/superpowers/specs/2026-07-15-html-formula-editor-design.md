# HTML Formula Editor Design

## Summary

Add a readable HTML template editor to Fireberry HTML formula fields. The editor lets a user write normally formatted HTML with dynamic field placeholders, preview the result with sample data, compile it to Fireberry formula syntax, and apply it to the existing formula input. Formulas generated by the editor can be converted back to readable templates when reopened.

## Goals

- Make HTML formula authoring readable and comfortable.
- Support dynamic Fireberry field values through `{{fieldName}}` placeholders.
- Show a realistic, safe preview using editable sample values.
- Generate a Fireberry-compatible, multiline formula and apply it without disrupting Fireberry form state.
- Reliably restore formulas generated by this editor to their template representation.
- Preserve unsupported existing formulas without silently changing them.

## Non-goals

- A visual or WYSIWYG page builder.
- Supporting every possible hand-written Fireberry formula in the decompiler.
- Executing JavaScript in the preview.
- Saving sample preview values into Fireberry.
- Changing Fireberry's native save behavior.

## User Experience

When Fireberry shows an HTML formula field, the extension adds an **Open HTML Editor** button near the native formula input. The button opens a large modal above Fireberry's current dialog.

The modal contains four coordinated areas:

1. **HTML template editor** — a multiline editor for normally indented HTML and `{{fieldName}}` placeholders.
2. **Preview data** — one editable sample value for each unique placeholder detected in the template.
3. **Live preview** — the rendered template after safe substitution of sample values.
4. **Generated formula** — a read-only view of the exact formula that will be placed in Fireberry.

The primary action is **Apply to formula**. Applying updates the native formula input and dispatches the input events Fireberry needs to update its React form state. Closing or cancelling the modal without applying leaves the native formula untouched.

## Template Syntax

Dynamic values use double-brace placeholders:

```html
<a href="https://wa.me/{{pcfsystemfield115}}">
  Click to WhatsApp
</a>
```

Placeholder identifiers must be non-empty valid Fireberry field identifiers. Repeated placeholders share one sample preview value and compile consistently at every occurrence.

For the initial version, all placeholder values compile through `HTMLENCODE(fieldName)`. This matches the intended safe default for inserting dynamic content into HTML formulas.

## Compilation

The compiler is a pure module independent of Fireberry DOM integration. It tokenizes a template into static HTML segments and field placeholder segments.

- Static segments become correctly escaped Fireberry string literals.
- Placeholder segments become `HTMLENCODE(fieldName)` expressions.
- Segments are joined with Fireberry's concatenation operator.
- Output remains multiline and intentionally formatted for readability.
- Template indentation and meaningful whitespace are preserved in the rendered HTML.

For example, the template above compiles conceptually to:

```text
"<a href=\"https://wa.me/" +
HTMLENCODE(pcfsystemfield115) +
"\">\n  Click to WhatsApp\n</a>"
```

The exact quote and newline escaping must be validated against the syntax accepted by the live Fireberry formula field before the integration is considered complete.

## Decompilation and Round Trips

The decompiler recognizes the deterministic structure emitted by this compiler and restores its `HTMLENCODE(fieldName)` expressions to `{{fieldName}}` placeholders. A compile-decompile-compile round trip must preserve the generated formula's meaning.

Existing hand-written formulas are handled on a best-effort basis:

- If the complete formula matches the supported grammar, it opens as a template.
- If it cannot be parsed without ambiguity, the original formula is kept unchanged.
- The editor shows a clear unsupported-formula state and does not enable applying a destructive conversion.
- No partial or guessed conversion is silently presented as authoritative.

## Preview Data and Rendering

The editor extracts unique placeholders and creates a sample-value input for each one. Sample values are local to the open editor session and are not included in the generated formula.

Before rendering, sample values are HTML-escaped and substituted for their placeholders. The output is written into a sandboxed iframe:

- Scripts are disabled.
- Top-level navigation is unavailable.
- Form submission is unavailable.
- The preview cannot modify Fireberry's document.

Template edits and preview-data edits update both the preview and generated formula immediately.

## Fireberry Integration

The DOM integration is separate from compiler, decompiler, validation, and preview logic.

The extension observes Fireberry dialog changes and identifies HTML formula inputs using stable DOM attributes and nearby labels where possible, with React-fiber metadata as a fallback. It injects at most one launcher for each eligible formula input.

On apply, the integration:

1. Assigns the generated formula through the native textarea/input value setter when required by React.
2. Dispatches bubbling `input` and `change` events.
3. Leaves Fireberry's own validation and save action in control.
4. Closes the editor only after the input update succeeds.

When the extension is disabled, it removes injected launchers and closes any open editor modal.

## Validation and Errors

The editor reports errors inline and disables **Apply to formula** for:

- Unmatched `{{` or `}}` delimiters.
- Empty placeholders.
- Invalid field identifiers.
- Compilation failures.
- Unsupported existing formulas that cannot be safely decompiled.

Closing an error state never changes the original Fireberry formula. Errors in the preview do not crash the host page.

## Component Boundaries

- **Template parser/compiler:** Converts validated HTML templates into Fireberry formulas.
- **Formula decompiler:** Converts only supported formula grammar back into templates.
- **Template validator:** Reports placeholder and conversion errors with source positions where practical.
- **Preview renderer:** Substitutes escaped samples and updates the sandboxed iframe.
- **Editor modal:** Owns local template, samples, errors, and apply/cancel interactions.
- **Fireberry adapter:** Detects eligible formula fields, injects launchers, reads native values, and applies generated values.

These boundaries keep Fireberry-specific selectors and event behavior replaceable without coupling them to formula conversion.

## Verification

Automated tests should cover:

- Static HTML compilation.
- Single, repeated, and multiple placeholders.
- Quote, backslash, whitespace, and newline escaping.
- Invalid and unmatched placeholder syntax.
- Compiler/decompiler round trips.
- Rejection of unsupported or partially parseable formulas.
- HTML escaping of preview sample values.
- Launcher deduplication and cleanup.
- Native value application and event dispatch.

Manual verification in Fireberry should cover:

- Detection of the HTML formula type shown in the field-configuration dialog.
- Successful acceptance and saving of generated multiline formula syntax.
- Reopening a saved generated formula as a readable template.
- Preview layout and modal behavior in both left-to-right code and Fireberry's right-to-left interface.
- Correct behavior after Fireberry rerenders or replaces the dialog DOM.

The production `bun run build` command must succeed before handoff.

## Delivery Scope

The first release includes the dedicated modal, template placeholders, sample preview values, sandboxed live preview, deterministic compilation, supported-formula decompilation, validation, native formula application, and extension cleanup. Advanced formula expressions, WYSIWYG editing, persistent preview samples, and arbitrary legacy-formula parsing remain future work.
